影响模型行为的主要因素

优先验证模型最终收到的请求，而不是只比较源码里的 prompt 文案。下表优先级表示复刻次序，不代表已实现。

优先级因素为什么影响行为当前证据 / 下一步
P0消息角色与通道system/developer/user 的权重、边界和来源不同；同一文本角色变化会改变指令层级。permissions / collaboration 插件当前用 user；Codex 对应 developer。DSH 已支持 developer message。核对插件可否发 developer。
P0每步状态更新与撤回世界状态变更是否及时到达模型、过期片段是否仍留在历史，影响其对当前权限、计划和环境的判断。对比 Codex world-state diff 与 DSH hash 短路及 projection；需要执行状态 A→B→A、字段删除测试。
P0真实上下文与消息历史项目指令正文、当前 cwd、用户/tool 结果是具体事实，不能由一段“遵循规则”的静态说明替代。验证 DSH agent-instructions 是否注入真实 AGENTS.md 正文；检查 cwd 双重注入与值一致性。
P0模型可见工具 schema模型只能调用请求中真实出现的工具及参数定义；YAML 声明不会自动证明部署已挂载。抓取最终 request header / assembly.tools，逐项比较 Codex 和 preset 部署。
P1循环与工具结果因果链工具结果如何回流、何时重试/继续、何时接收新输入，决定 agentic 行为边界。两端 loop 源码已有证据；对齐 parallel/exclusive barrier 与错误恢复细节。
P1请求模型参数reasoning、输出约束、verbosity、并行工具及服务等级会影响输出和工具选择。Codex 请求字段已核验；当前 DSH route 实际参数需从模型请求日志/适配层核验。
P2静态 prompt 文案与顺序定义默认策略，但若消息角色、历史状态、工具 schema 不一致，仅微调措辞收益有限。preset sections 已核验；personality 旧提取逻辑与旧注释需清理/核对，暂不在本阶段改逻辑。
P3生命周期事件与 UI 表达主要影响可观察性和交互边界，通常不如模型可见上下文直接。根据任务类型再评估；仅有事件而未进入模型输入的差异通常不先复刻。

复刻顺序建议

P0 · 先确认最终请求。 采集一次真实 DSH 请求的有序消息数组、角色、工具 schema 和参数，然后与 Codex 请求结构对照。先把 permissions/collaboration 的 developer 角色差异查实。

P0 · 做状态转换测试。 验证 sandbox/approval、协作模式、cwd 变化及撤回时，旧 fragment 是否仍可影响后续模型步。

P0 · 确认事实性上下文。 检查真实 AGENTS.md 正文、working-directory context 和 environment XML 的最终重复情况。

P1 · 对齐工具和执行边界。 核实挂载后的工具列表、并行/独占语义、工具结果回填、失败恢复与继续策略。

P2 · 再调静态文案。 确保 personality 与上游 e6de6a2 现状一致；之后再处理静态指令措辞、顺序和不必要的重复。

本轮结论 · 收窄范围。 preset 只保证 permissions → collab → environment → working-directory 快照这四段的相对顺序；AGENTS.md、skill catalog、time context 由其它插件决定，不再为“完整对齐”搬动。developer role、撤回语义等差异按“单步消息顺序与角色”一节的已知差异表跟踪。
